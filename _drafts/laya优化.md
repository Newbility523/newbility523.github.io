# Laya 优化记录

## 场景静态合批

在项目早期，并没有明确场景的制作规范，导致虽然已经将场景资源设置为 static，在 Laya 侧看到的场景 drawCall 依旧很高。本质原因是静态合批的对象还需要贴图和材质球一致。不明确的规范使得场景资源即使是同一个类似对象，例如石头，存在 4 种，就有 4 套材质球和贴图。

基础数据记录项：

- 建筑、装饰、石头数量
- drawCall
- 静态合批：-20 ~ -30 drawCall
- saveBatch：+N

场景对象依旧能达到 1000 个。

## Culling 优化

### 离线静态合批

静态合批的工作流程是加载场景后将 a 和 b 网格在运行时合并成 ab，实际渲染会用这份 mesh。可以通过开关静态合批发现，关闭静态合批时资源 GPU 占用 179M，开启后 220M。所以更优的策略是提前将网格做离线静态合批。

## 修复 GPU 内存问题

处理完后对比数据：CPU +20M（原来 20M），GPU +100M（原来 220M）。

开了离线合批后，是不需要再设置 isStatic 的，因为已经手动静态合批，勾选属性会导致合并的网格再合并一份。其次是因为实现过程兼容性问题，额外多加载了一份高清贴图，移除即可。

### 移除 CPU 侧内存

那么此时还有个异常问题，CPU +20M，基本翻倍来自哪里。

网格进行渲染默认情况下其实就是 CPU 和 GPU 都有一份，用于同步 CPU 侧对网格的调整或者读取上面的属性。但是对于静态的场景物件没有这个需求，其实就是 Unity 中导入模型的 Read/Write 选项的功能。既然没有，就关掉。CPU 内存回到原本水平甚至略低。

## 场景 Shader 单面渲染

场景非透明对象不选渲染背面，但是这个问题在 Unity 侧属性是好的，导出到 Laya 没有指明，默认取到了两面都不剔除。改导出工具。

## 动画优化

### 降低采样

动画的导入误差范围设定的是 0.5,0.5,0.5。一眼看过去，很容易误解为动画资源导入误差以为是 0.5 这个值，实际上是 0.5/100，也就是误差不超过 5/1000，已经非常小了。对于一些飞天遁地，速度比较快但是有比较长的动画，这里参数其实可以大胆设置，起码可以设置成 3,3,3，我最终设置的是 3,10,3。动画的尺寸降低了 1/3，实际运行内存甚至降到了 50%。但是这个只能作为参考值刷一遍，有问题的话，再细调。作为写死的动画导入参数，对于动画较短的资源误差会比较明显，例如脚部发抖。

### 冗余动画移除

记录跑一圈的加载动画资源，发现一些头部动画因为预加载配置错误加载了，删掉。

以上降低 20M，原来 70M 运行内存。

### 屏幕外动画屏蔽

发现生命周期中，有一段较长的固定时长来自 Clip、setNodeData，查源码发现来自动画，动画机需要每帧计算动画。场景动画其实不多，但是耗时却和场景的渲染相当，这非常不合理。并且打开全屏 UI 界面，这块没有变化，说明没做遮挡剔除。

### 冗余动画轨道移除

移除冗余判断，调整判断逻辑，最终降低场景动画 40% CPU 耗时。降低 60M 左右的资源尺寸。
